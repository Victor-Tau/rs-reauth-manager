# 账号重新授权

RS 网关独立插件，支持手动及按条件自动重新授权，也支持使用邮箱、密码与 2FA 密钥导入新账号。重新授权沿用原账号备注及绑定代理，成功后写回原账号

**当前状态：实验性功能**，当前源码面向 RS v3.29.1，尚未完成该宿主版本的实际安装及真实账号完整登录与写回验证，请先在测试实例和自有测试账号上验证，不建议直接批量操作生产账号

## 安装

在 [Releases](https://github.com/Victor-Tau/rs-reauth-manager/releases) 下载对应版本的 `.tar.gz` 与 `.sha256`，核对摘要后，在 RS 的插件管理中上传安装

也可以使用 GitHub 来源安装，仓库填写 `Victor-Tau/rs-reauth-manager`，标签可填写 `v0.13.0` 或留空查询最新已公开发行版，选择插件 `.tar.gz` 附件，不是 GitHub 自动生成的 Source code 归档

本仓库发布 Victor-Tau 维护的 0.13 系列，安装与升级请使用本仓库的 Releases，不要使用上游项目中的旧发行版。

当上游没有返回任何候选工作区时，管理员可以选择“退回 Free”。该操作需要单独确认，会重新获取同一用户的 Free 授权，写回原账号并停止调度；不需要猜测或填写工作区 ID。

暂不提供 ARM64、Windows 或 macOS 宿主安装包，前端可由桌面和手机浏览器访问

## 0.13 分组筛选与退出所有登录

“账号重新授权”列表支持按全部分组、未分组、指定分组显示，显示各组账号数量，多分组账号可从任一所属组查看。分组与搜索、订阅、状态筛选共同生效，切换分组清空旧选择并回到第一页，避免批量操作包含上一组账号。

“退出所有登录”与重新授权并列，支持单号或勾选账号批量提交。确认后使用每个账号当前的访问令牌及其绑定代理，向 `https://chatgpt.com/backend-api/accounts/logout_all` 发送空正文 POST；按抓包契约，仅 `HTTP 200` 且 JSON 为 `null` 时确认成功。不使用 HAR 中的账号资料，不在页面传递令牌，不需要备注中的密码或 2FA，也不会为了退出而自动登录或刷新授权。

操作会退出该账号所有设备的登录，可能使 CPR 当前授权失效。**执行前停止所选账号调度，并阻止后台自动重新授权**，保留其他配置及现有凭据；恢复使用时请手动重新授权，核对后按需启用调度。缺少代理或访问令牌、账号在途请求不为零、凭据与账号不匹配时停止。排队期间重新检查凭据版本及代理状态；任务与重新授权共用串行队列，插件总开关和停止队列同样生效。

未授权、权限不足或限流显示退出失败；超时、断连、异常响应及配置变化显示需要核对，不会自动重试退出或自动重新登录。重复请求 ID 不重复排队，重启后不重放未完成退出。取消只能阻止未发出的请求，已发出的退出请求可能已生效，需要核对设备状态。

已通过模拟宿主、离线 HTTP 和浏览器测试，尚未使用真实账号验证退出接口接受当前 CPR OAuth 授权的情况；若上游拒绝授权，将保留停止调度状态并显示具体 HTTP 状态。

## 0.12 新增功能

### 自动授权参数配置

在“参数配置”页开启自动重新授权，按**分组、账号状态和订阅类型同时匹配**筛选账号。每种条件内的多选项满足任一项即可，支持全部分组、指定多个分组、未分组，及全部或指定订阅（包含 Free 和未知套餐）。状态可选择异常、正常、额度耗尽和限流，默认仅异常；默认只处理已启用调度的账号。

自动授权默认关闭，不会因更新插件自动登录。扫描间隔可设 1–1440 分钟，同一账号冷却可设 1–168 小时，默认分别为 15 分钟和 24 小时。配置、扫描时间和账号冷却均保存在插件状态中，刷新或重启后保留。CPR 当前每约 30 秒调用维护接口，页面关闭后仍推进扫描和串行任务，实际执行时间以宿主维护调度为准。

资料或代理缺失、账号不空闲、已有任务及冷却中的账号不会执行。写回结果不确定或进程中断会阻止自动重试，核对并手动授权成功后解除。后台每批最多排队 100 个，冷却及阻止记录最多保留 1000 个账号；达到上限会等待记录过期或人工核对解除，不淘汰保护记录。更新配置会取消尚未执行的自动任务，已运行任务继续核对并完成。停止队列只取消当前任务，后续扫描由自动授权开关控制。

### 账号导入

在“账号导入”页填写邮箱、密码、Base32 2FA 验证器密钥（不是六位动态码），或将 `邮箱----密码----2FA` 整行粘贴到“粘贴登录资料”或邮箱栏自动拆分，即可使用 CPR 原生 OAuth 建立新账号。支持名称、工作区 ID，以及与 CPR v3.29.1 官方 OAuth“编辑账号”一致的参数：

- 上游传输：WS（`prefer_websocket`）或 SSE（`http`）
- 启用调度（默认开启）、并发限制（留空或 1–4294967295）、权重（1–100，默认 5）
- 分组多选、出站代理或直连
- 全部模型、模型允许列表或拒绝列表（1–256 个精确模型 ID）
- 最多 500 字备注

账号先以停用状态创建，验证邮箱及新授权、设置传输方式并读回核对参数后，才按所选设置启用。订阅和上游身份由实际授权决定。个人 Plus 等账号未返回工作区信息时，工作区 ID 可留空，使用已校验的 OAuth 回调继续导入；单一工作区自动选择，多个工作区时停止并列出候选 ID，可选择后重新提交。当前队列结束后可逐个导入，已有同邮箱 OAuth 账号请使用重新授权。

认证代理优先从所选代理关联账号的原生导出中读取完整地址；未有关联账号时可手填本次登录用的完整认证代理地址，必须与所选代理 endpoint 一致。登录前及提交前检查代理仍启用且版本未变，完成后精确核对代理关联。

默认勾选“将登录资料保存到 CPR 账号备注”，用于后续自动授权；可取消勾选以仅保存自定义备注。勾选时会替换备注为 `邮箱----密码----2FA`。插件任务历史不保存密码、2FA、完整代理、回调或令牌，页面提交成功或离开时清空秘密输入。部分导入失败保留已创建账号 ID 并要求核对，不自动重建或删除账号。

这些功能已通过离线模拟测试，真实账号及宿主安装仍需验收。

## 使用

1. 在 RS 原账号备注中填写 `邮箱----密码----2FA`，两处分隔符都是四个连字符，2FA 是 Base32 验证器密钥，不是当前六位动态码
2. 确认备注邮箱与原账号邮箱一致，并已绑定该账号自己的代理
3. 在插件中搜索或筛选账号，单号执行或勾选后批量提交，确认后进入串行队列
4. 查看处理进度及结果，失败、结果不确定或中断时先核对原账号，再手动决定是否重试

支持会员和状态筛选、10/20/50/100 条分页、选择当前页、停止队列及单号取消
工具栏提供插件开关，默认开启，状态保存在后端，刷新页面或重启插件后保留。关闭会停止当前协议进程、取消排队任务并阻止常规授权、强制写回和退回 Free；重新开启不会恢复已取消任务，需要手动重新提交。已经提交的授权不能撤销。
“确认重新授权”等提交按钮兼容 HTTP 页面中缺少 `crypto.randomUUID` 的浏览器环境，使用 `crypto.getRandomValues` 生成任务标识；浏览器能力不足或提交失败时在页面显示错误。
账号后显示 RS 原生分组，多个分组全部列出，没有分组时显示“未分组”；搜索支持分组名称，展示不修改账号分组配置
顶部“可处理”按全部适用账号中 RS 状态为异常的账号数统计，包含备注或代理尚未齐全的账号；这类账号仍须补齐资料并空闲后才能提交
“成功”和“未完成”只统计本页最近一次提交的任务，单号和批量提交均会开始新的一次统计；重新进入插件或刷新整个页面时归零，不删除后台历史记录
点击“成功”或“未完成”会列出本次对应账号并清除无关搜索、会员筛选和分页位置；普通读取最新账号不会清空本次结果
“队列”仍显示后台实际排队及运行中的任务数，重新进入页面不会取消已有任务或将其结果混入本次统计
Free、Plus、Pro、Team、Business 等全部套餐的 OAuth 账号均可列出、筛选和重新授权；API Key 或其他提供商账号不适用这个登录协议
缺少代理或登录资料时仍拒绝执行，不回退到直连或其他账号代理；本插件的账号范围与周限／重置卡插件独立，后者的 Free 排除规则不受影响
原工作区在已登录会话中确认不可用，且唯一明确的个人工作区确认为同一用户的 Free 时，使用上游协议获取新的 Free 授权，停用原 RS 账号后通过公开 SDK 写回原账号，不新建账号、不修改分组
完整读回验证通过后显示“登录成功：原工作区已失效，已切回 Free，已停止调度”，计入本次成功；无法确认身份或工作区时不降级，停用或写回结果不确定时显示需要核对且不自动重试

## 安全与边界

### 具体错误显示

新失败任务显示白名单内的失败阶段、原因和可用的最后 HTTP 状态，例如“创建 2FA 验证挑战”“未找到 TOTP 验证器”“上游拒绝动态码”“上游限制登录频率”“请求超时”“邮箱验证码待人工处理”。2FA 流程失败不再统一归因于备注密钥错误。
错误由协议层和 Rust 后端双重白名单投影，不透传上游正文、未知错误文本、URL、请求头、验证码或凭据。没有足够证据时明确显示未取得具体原因，不猜测代理或密码错误。
旧通用错误仅在展示时标为“历史记录，未记录具体原因”，原任务历史保持不变，不能还原未保存的原因；只有以后手动发起的新任务才会记录新诊断，更新插件不会自动重登账号。

新任务会记录详细日志：在账号列表点击“查看日志”，或在导入页的“最近导入任务”中展开“详细日志”。可查看时间、处理阶段、请求方法、HTTP 状态、耗时、响应类型与大小、页面类型、工作区候选数量及回调/state 校验结果，选中文字即可复制。每任务最多保留最近 100 条，日志总容量有界并优先保留最新任务；较早记录会清理，旧版本任务不补录。日志不保存密码、2FA 动态码或密钥、令牌、Cookie、完整授权 URL、代理认证或上游响应正文。

授权确认页返回 HTTP 200 不表示已完成授权。v0.13.0 增加对页面 JSON、React Router 索引数据及流式脚本的工作区提取，兼容会话 Cookie 没有工作区、但页面包含个人工作区的情况，仍须取得有效且 state 匹配的回调。已用用户授权的 Free 测试账号实际验证密码、2FA、页面工作区选择及回调；没有交换/保存令牌、创建 CPR 账号或退出其他设备，个人 Plus 尚待实测。

### 管理员强制写回其他工作区

当任务因“无法匹配原账号工作区，已停止写回”失败时，账号操作列提供“强制写回”入口。
新失败任务只保存从已登录会话提取的工作区 ID，不保存 RT、密码、2FA 或代理认证。
管理员必须选择一个明确工作区，并勾选“替换原授权并停止调度”后，才会创建逐号强制授权任务；默认不选工作区、不勾选确认，也不提供批量强制开关。
旧失败任务没有工作区列表时，先点击“重新检测工作区”走常规登录，取得列表后再打开强制写回确认。

强制任务会重新登录，复用原代理，使用独立 PKCE 换取所选工作区的授权；仍校验同一邮箱、用户身份、授权主体、工作区和令牌有效期，不允许把其他用户的 RT 写入此账号。
新工作区可以是 Free、Plus、Team 等套餐，以实际验证的新授权为准。写回前检查账号空闲、配置及凭据版本未变，然后停止该号调度，精确版本写回原记录并读回验证；保留名称、备注、分组、代理、权重、并发和模型权限。
停止调度或写回结果不确定时显示“需要核对”，不自动重复登录或写回，也不自动恢复调度。
此功能允许管理员明确替换工作区身份，属于新增行为，源码版本为 0.1.10；网站更新与 GitHub Release 分别处理，已发布附件保持不变。

- 安装使用 `trustedProcess`，意味着完整信任插件，不是操作系统沙箱，请审查源码和发行包来源
- 重新授权时密码、2FA、完整代理地址和一次性回调只在内存与私有进程管道中传输，不写入任务状态或普通日志；导入页面通过宿主桥提交手工输入，导入默认勾选保存登录备注，可取消
- 常规授权由 RS 原生 OAuth 流程交换和保存 RT；已验证的 Free 恢复使用未修改的上游换取令牌协议，并通过 RS 公开 `host.auth.save` 精确凭据版本校验写回，RT 只经过私有管道与 SDK 二进制载荷，不在页面展示、下载或导出
- 为读取带认证代理，后台按精确单账号调用 RS 原生敏感导出接口，只取代理 URL，不持久化或向前端提供导出的凭据
- 登录及写回前通过公开代理目录和精确账号关联检查代理已启用，并将代理 ID 与 revision 纳入配置校验；代理禁用、绑定或版本变化以及无法确认状态时停止，不因账号仍显示代理地址而允许直连
- 保留原账号的名称、分组、代理、权重、并发限制和模型权限，不启用、不改组，也不使用重置卡；常规授权保留启用状态，Free 恢复或管理员确认强制替换工作区时关闭该账号调度，原本停用的账号仍停用
- 登录和写回前必须观测到账号在途请求为零，状态未知时停止，这不是跨系统流量锁，持续接收新请求的账号需要管理员选择空闲窗口
- 登录期间配置或凭据版本变化时停止写回，工作区无法确认时停止，不默认选择第一个工作区；管理员确认只放宽原工作区匹配要求，不放宽用户身份、并发与凭据版本检查
- 不绕过手机号、验证码或其他人工验证要求，遇到这些步骤时需要人工处理
- 取消可以终止尚未提交的协议进程和后续任务，不能撤销已经提交的授权，进程重启及不确定结果不会自动重放登录
- 每次最多排队 100 个账号，串行执行，单号超时 420 秒，自动重新授权由 CPR 维护回调扫描，需在参数配置页显式开启

请仅处理自己拥有或明确获授权的账号，并遵守服务条款

## 协议与上游

协议模块来自 [boji1334/reauth-web](https://github.com/boji1334/reauth-web)，固定提交 `db8251817fd1baefc83c14c851135fb6078bc001`
仅保留登录必需的五个 `vendor/lib` 模块与 RFC 6238 TOTP 实现，不依赖重登站，不包含兑换、支付、账号注册或其 Web 服务
原模块保持不变，适配代码在 `protocol/runner.py`，原始 MIT 许可位于 `protocol/LICENSE.reauth-web`
适配层接受 RS 返回的官方桌面授权外层链接，仅拆出并校验 `authorize_url` 后交给上游协议；常规路径不重新生成或替换 RS 的 state、PKCE、client_id 和回调地址，也支持直接 OAuth 链接
只有已验证的 Free 恢复路径使用上游 `generate_pkce` 生成独立的 state 和 PKCE，保留已校验的 client_id 与回调地址，复用同一代理及登录会话；绝不拿 RS 待完成流程的授权码搭配其他 verifier 交换

后端使用 RS v3.29.1 的公开 SDK，固定提交 `743a3aba70a4f78f27fb53d80a6e719599d2fe5e`；构建安装包时使用同一提交的 `cpr-plugin`，由 CLI 生成 RPC v4 安装清单
界面使用官方 `@codex-proxy/ui` v0.4.1 编译发行包，并参考 [插件工作台示例](https://github.com/zyycn/codex-proxy-plugins) 组织公开宿主桥、请求层、业务解码和 composable
不跨仓导入宿主内部源码，不读取管理 Cookie，也不直接访问宿主数据库

第三方来源与许可见 [NOTICE](legal/NOTICE.md) 和各协议、依赖的原始许可

## 构建安装包

Linux 协议运行环境包含在发行包内，安装者无需在服务器装 Python 或依赖
运行包展开到宿主解出的插件目录中的随机私有子目录，权限为 0700，插件进程正常退出时清理；强制终止或宿主崩溃可能留下运行目录
该数据盘需可写、可执行并至少预留 256 MiB 空间，不依赖系统 `/tmp` 的容量或执行权限，不修改网关的只读根目录、挂载与 CPU/内存配置
登录前会先解包并检查 Python、TLS、协议依赖、TOTP 和离线桌面授权链接解析契约，失败时不会发起原生授权流程
管理员可通过已注册管理路由 `POST api/runtime-check`、正文 `{}` 单独执行自检，自检不读取登录资料、不访问上游、不创建账号任务

本地准备 Python 依赖及 [crane v0.20.6](https://github.com/google/go-containerregistry/releases/tag/v0.20.6)，然后执行

```bash
python -m pip install -r requirements-dev.txt
python scripts/prepare_runtime.py --crane /path/to/crane
python scripts/build_runtime.py
```

准备脚本按固定镜像摘要下载 Linux x86_64 Python 基础镜像，不需要 Docker daemon，不访问应用服务器
wheel 版本与 SHA-256 固定在 `protocol/requirements-linux.txt`，构建时校验镜像各层，并按 ELF 依赖闭包打包
缓存默认位于仓库内 `.cache/runtime`，不会提交到 Git
已有公开输入时可以用 `build_runtime.py --base-tar <file> --dependencies-dir <directory>` 指定其路径

Linux 原生构建示例

```bash
cargo +1.97.0 build --manifest-path backend/Cargo.toml --release --locked --target x86_64-unknown-linux-gnu
cpr-plugin package --manifest plugin.json --binary backend/target/x86_64-unknown-linux-gnu/release/reauth-manager --target x86_64-unknown-linux-gnu --resource-map web=frontend/dist --output-dir dist
python scripts/verify_artifact.py
```

Windows 交叉编译需先配置 Zig 与 cargo-zigbuild，将构建命令换成 `cargo +1.97.0 zigbuild --manifest-path backend/Cargo.toml --release --locked --target x86_64-unknown-linux-gnu.2.28`
`cpr-plugin` 使用与上文 SDK 相同的固定提交构建，生成的制品及校验文件位于 `dist/`

## 验证范围

SDK 子进程测试覆盖 RPC v4 握手、独立请求上下文和业务 JSON 分段、无入口请求的维护调用，以及常规授权、Free 恢复、管理员确认、精确凭据版本冲突和不确定结果不重放
代理测试覆盖同 endpoint 的不同账号绑定、禁用与未知代理、登录期间版本和启用状态变化，以及目录和关联账号的分页

Python 离线测试覆盖协议适配、未修改的上游 OAuth 代码、独立 PKCE、身份保护、具体错误脱敏和 HTML 资源边界；Rust 测试覆盖账号范围、诊断和运行目录生命周期
前端测试覆盖宿主桥、业务响应解码、Vue 生命周期、本次任务统计和分组搜索，源码检查覆盖公开依赖、SFC、主题及资源约定
制品校验检查 RPC 与能力版本、宿主范围、文件摘要及协议文件一致性，拒绝生产包中的测试入口和不受宿主支持的 HTML 资源引用

这些测试使用模拟宿主和虚构账号，不访问真实上游，不能代替 RS v3.29.1 的实际安装及真实账号完整链路验收；代理、账号状态、工作区和人工验证仍可能导致实际登录失败
